# 把本项目做成 SaaS 的可行性报告

> 一句话结论：**技术上能做、产品方向对，但不是"改个登录就上线"，而是要补一层"多租户 + 安全沙箱 + 计费"的平台外壳；最大的两个拦路虎是开源协议（AGPL）和安全隔离成本。建议分三步走，先做"半托管/私有部署"快速变现，再做"全托管 SaaS"。**
>
> 最后更新：2026-06-01 · 适用对象：决策与商务

---

## 一、先认清这是个什么底子

| 维度 | 现状 | 对做 SaaS 的影响 |
|------|------|------------------|
| 产品定位 | 任务型 AI Agent 工作台（PilotDeck），自带 WorkSpace 隔离、白盒记忆、智能路由、后台常驻 | 内核很值钱，是差异化卖点 |
| 已整合能力 | Open Design 设计系统（150 套）+ 27 个出图技能、生图/生视频、Figma、营销/公关 Skills 与 MCP 选型 | 内容创意场景已能闭环，适合做"营销创意 SaaS" |
| 运行形态 | 现在是**单机单用户**：所有数据存本机 `~/.pilotdeck`，Docker 也是单实例 | 直接对外开放等于"所有人共用一个账号"，必须改造 |
| 开源协议 | **AGPL-3.0** | ⚠️ 关键限制，见第四节 |
| 代码体量 | Node/TypeScript 单体 + React 前端 + 网关，已有 Docker | 起步工程量可控，不用推倒重来 |

**白话**：核心引擎已经很能打，缺的是"把一个人用的工具，变成一万人同时安全使用、还能自动收钱"的那层壳。

---

## 二、改造难度（从单机到 SaaS 要补什么）

按"必须做"的优先级排序：

| 模块 | 要做什么 | 难度 | 说明 |
|------|----------|------|------|
| 多租户隔离 | 每个用户独立的 WorkSpace、记忆、文件、配置，互不串台 | 中 | 内核本来就有 WorkSpace 概念，是顺势改造，不是从零 |
| 账号与权限 | 注册登录、团队/成员、套餐、配额 | 中 | 有现成方案（如 Clerk/Auth0/自建），属于成熟活 |
| **安全沙箱** ⭐ | Agent 会跑代码、命令行、浏览器——必须把每个用户的执行环境关进独立容器/虚拟机 | **高** | 这是最难、最烧钱的一块；做不好就是安全事故 |
| 计费与额度 | 按订阅 + 按用量（Token/出图/出视频）扣费、钱包、账单 | 中 | 需要精确计量，好在内核已能"按任务统计 Token" |
| 模型与密钥托管 | 平台统一出 API Key，用户不用自己填；按用量结算 | 中 | 现有"模型池+供应商凭据继承"机制是好基础 |
| 资源限流/常驻管控 | "后台常驻"很香但很费钱，必须能限制并发、空闲回收 | 中高 | 否则成本会失控 |
| 可观测与运维 | 监控、日志、告警、扩缩容 | 中 | 标准 SaaS 运维 |
| 合规 | 数据安全、备案（国内）、内容审核 | 中 | 国内上线必做 |

**总体难度评估**：中高。其中 **80% 的难度集中在"安全沙箱"和"成本失控防护"** 两件事上。其余都是成熟的、有现成轮子的工程活。

> 估算工期（2–4 人小团队）：能用的最小版本约 **2–3 个月**；可商用、较稳的版本约 **5–8 个月**。

## 三、可行性结论

| 看的角度 | 结论 | 理由 |
|----------|------|------|
| 技术可行性 | ✅ 可行 | 内核已有隔离/记忆/路由，缺的是平台外壳，无技术死路 |
| 商业可行性 | ✅ 有市场 | "营销创意 + AI Agent 自动产出物料"是真实付费场景 |
| 差异化 | ✅ 较强 | 白盒记忆、智能路由省钱、150 套设计系统、能直接产出落地页/海报/视频，竞品少有齐全 |
| 主要风险 | ⚠️ 三个 | ①AGPL 协议 ②安全沙箱成本 ③Token/媒体成本波动 |

**一句话**：值得做，但要把它定位成"**AI 营销创意生产平台**"这种垂直 SaaS，而不是又一个通用 Agent，否则打不过大厂。

---

## 四、最关键的坑：开源协议（务必先解决）

本项目是 **AGPL-3.0**。它的特殊之处：**只要你把它当成网络服务（SaaS）对外提供，就必须把你修改后的全部源代码开放给使用者。**

这意味着三选一：

| 方案 | 做法 | 适合谁 |
|------|------|--------|
| A. 合规开源 | 你的改造也按 AGPL 开源（核心商业逻辑/Prompt 可拆成独立服务规避） | 接受开源、靠服务/算力赚钱 |
| B. 商业授权 | 联系上游 OpenBMB/清华团队购买商业许可（dual-license 谈判） | 想闭源商用、有预算 |
| C. 改架构规避 | 把计费、租户、私有 Prompt 等做成**独立的、不与 AGPL 代码链接**的外部服务，AGPL 部分照常开源 | 多数务实团队的折中 |

> **行动项**：上线前先找律师/上游确认授权方式。这一步不解决，后面全是法律风险。

## 五、成本结构（钱花在哪）

分两类：**一次性投入** 和 **持续成本**。

### 5.1 一次性 / 研发投入

| 项 | 估算（人民币） | 说明 |
|----|----------------|------|
| 平台改造研发 | 15万–50万 | 2–4 人 × 3–8 个月，取决于做到哪一档 |
| 安全沙箱方案 | 含在上面或额外 5万–15万 | 自建 vs 用现成（如 E2B、Firecracker、gVisor） |
| 法务/授权 | 1万–10万+ | 协议合规、合同、商业授权谈判 |
| 设计/品牌/官网 | 2万–8万 | 可用本项目自己产出，省一笔 |

### 5.2 持续运营成本（按月）

| 成本项 | 起步规模 | 备注 |
|--------|----------|------|
| 服务器/容器算力 | ¥3,000–¥15,000/月 | 沙箱按"活跃用户并发"扩缩，常驻任务越多越贵 |
| 数据库 + 对象存储 | ¥1,000–¥5,000/月 | 文件、产物、记忆数据 |
| **LLM Token（最大变量）** | 按用量，**强烈建议转嫁给用户** | 智能路由可省约 70%，是核心卖点也是护城河 |
| 生图/生视频 | 按用量转嫁 | 图≈¥0.1–0.5/张，视频≈¥1–10+/条 |
| CDN/带宽 | ¥500–¥3,000/月 | 媒体产物分发 |
| 监控/三方服务 | ¥500–¥2,000/月 | 监控、邮件、短信、支付通道 |

> **核心成本观**：**固定成本可以压得很低（几千到几万/月起步）**，真正的大头是 Token 和媒体生成——这部分**不要自己扛，要按量计入用户账单**。智能路由帮你把"主力贵模型只在关键节点用、杂活交给便宜模型"，这是省钱护城河，要重点宣传。

## 六、收费建议

### 6.1 推荐模式：订阅 + 积分钱包（双轨）

把"用平台的权利"和"消耗的 AI 算力"分开收，避免 Token 价格波动吃掉利润。

- **订阅**：解锁功能、席位、并发、常驻能力、技能包。
- **积分/Credits**：按实际消耗的 Token、出图、出视频扣减；用完可加购。

### 6.2 套餐示例（仅供起步参考）

| 套餐 | 价格 | 含算力额度 | 主要权益 | 目标人群 |
|------|------|-----------|----------|----------|
| 免费版 | ¥0 | 少量体验积分 | 基础出图/落地页，带水印，**无后台常驻** | 试用、获客 |
| 个人 Pro | ¥99–¥199/月 | 含一定积分 | 全部创意技能、生图、Figma、去水印 | 自由职业、个人创作者 |
| 团队版 | ¥99–¥299/席/月 | 团队共享积分池 | 多成员、协作、品牌库、优先队列 | 营销团队、广告小公司 |
| 企业/私有 | 定制（年付为主） | 按量或包断 | 私有部署、独享沙箱、SSO、SLA、定制技能 | 中大型企业 |
| 加购积分 | ¥X/1000 积分 | — | 用完续费，按成本 + 30%–60% 加价 | 所有付费用户 |

### 6.3 定价原则

1. **算力按成本加价 30%–60% 转嫁**，平台不替用户烧 Token。
2. **常驻/后台任务单独计费或限高档套餐**，因为它最费钱。
3. **生视频等高成本能力单独按条计**，不要打包进低价套餐。
4. 免费版只做"获客漏斗"，严格限额、带水印、禁常驻。
5. 企业私有部署是高毛利单子，优先卖给有预算的客户（也顺带规避部分多租户/沙箱成本）。

## 七、建议的落地路线（三步走）

| 阶段 | 目标 | 内容 | 时间 | 变现 |
|------|------|------|------|------|
| 第一步：私有/半托管 | 快速验证 + 现金流 | 给企业客户做**私有部署 + 定制技能**，按项目/年费收钱；几乎不用做多租户和沙箱 | 1–2 个月 | 立刻能收钱，验证需求 |
| 第二步：托管测试版 | 跑通 SaaS 闭环 | 做账号、计费、积分、基础沙箱，限量邀请制内测 | +2–3 个月 | 个人/团队订阅 |
| 第三步：正式 SaaS | 规模化 | 强化安全沙箱、自动扩缩、常驻管控、合规备案 | +3–4 个月 | 全量开放 |

> **强烈建议先走第一步**：用"私有部署 + 定制"边赚钱边验证哪些技能最值钱，避免一上来就投入做最难的全托管沙箱。这也符合"外部项目逐个落地"的一贯节奏。

## 八、风险与应对速查

| 风险 | 影响 | 应对 |
|------|------|------|
| AGPL 协议 | 法律 / 闭源受限 | 上线前确定授权方式（开源合规 / 商业授权 / 架构规避） |
| 安全沙箱 | 用户代码越权、数据泄露 | 用成熟沙箱方案（E2B/Firecracker/gVisor）+ 每租户隔离 |
| 成本失控 | 常驻任务烧钱 | 算力转嫁用户 + 并发限流 + 空闲回收 |
| Token 价格波动 | 利润被吃 | 积分钱包按成本加价，不做固定包干 |
| 内容合规（国内） | 下架风险 | 接入内容审核 + 备案 |
| 大厂竞争 | 通用 Agent 卷不过 | 聚焦"营销创意垂直 + 中文设计系统"差异化 |

---

## 九、给决策者的三条建议

1. **先卖私有部署/定制，别急着做全托管**——最快见钱，最低风险。
2. **协议问题第一优先级处理**——这是唯一可能让项目"白做"的硬伤。
3. **定价采用"订阅 + 积分"双轨**，算力成本全部按量转嫁，用智能路由省钱作为核心卖点。
