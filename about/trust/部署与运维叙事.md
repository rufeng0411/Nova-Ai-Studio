# 部署与运维叙事

> Executive Summary (EN): Nova ships via Docker on Alibaba Cloud ECS; install/upgrade scripts preserve data and .env; PG + Redis recommended; pack:deploy for releases.

---

## 部署形态

| 形态 | 适用 |
|------|------|
| **全托管 SaaS** | 公网多租户（阶段 3）|
| **私有 Docker** | 企业内网 / 专属 ECS |
| **本地 dev:saas** | 开发演示 `npm run dev:saas` |

---

## 阿里云私有部署（已备路径）

```
本机 pack:deploy → OSS → 客户 curl install.sh
  → 灌入镜像 + 配置
  → DATA_ROOT 持久化（如 /var/lib/nova）
  → upgrade.sh 仅换镜像，不覆盖数据与 .env
```

**销售话术**：「升级程序不覆盖你们数据和配置，和换软件版本一样。」

---

## 组件清单

| 组件 | 作用 |
|------|------|
| UI + Bridge | Express / Vite 生产包 |
| Gateway | Agent 执行与 WebSocket |
| PostgreSQL | SaaS 控制面（用户、租户、workspaces）|
| Redis | 验证码、缓存 |
| Nginx | 静态资源、反代 |

构建期：镜像内启用 SaaS 模式（按部署模板配置环境变量）

---

## 数据持久化

| 数据 | 位置 |
|------|------|
| 租户项目与云端文件 | `DATA_ROOT/tenants/...` |
| 控制库 | PG `SAAS_DATABASE_URL` 或开发 SQLite |
| 技能库 | 平台技能目录（部署文档按环境配置）|

---

## 运维卖点

- 一键安装 / 升级脚本
- 不覆盖线上 `.env` 与数据目录
- 健康检查：`/api/saas/health`
- 验收：`npm run test:saas:acceptance`（交付前内部）

---

## 客户 FAQ 简答

**Q：停机升级多久？**  
A：换镜像滚动，分钟级；会话建议低峰操作。

**Q：能否只用国产库？**  
A：PG/Redis 可客户自备；模型池可偏国产供应商。

**Q：单机版能否与 SaaS 并存？**  
A：产品双轨；商业化分开谈。
